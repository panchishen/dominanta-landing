# Доминанта — лендинг

Лендинг для https://dominanta74.ru/. Основа — проект Dental AI. Чистый HTML/CSS/JS, без сборщика.

## Для разработчика: публикация на боевой домен

### Какую версию брать

**Только последний релиз:** https://github.com/panchishen/dominanta-landing/releases/latest

- Каждый релиз (`v1.0`, `v1.1` …) — версия, согласованная заказчиком. К релизу приложен `site.zip` и список изменений.
- Ветка `main` и GitHub Pages — рабочая версия в разработке. **На домен её не заливать.**

### Как выложить

1. Распаковать `site.zip` и положить содержимое в корень домена как есть. Сборка не нужна. Пути относительные, поэтому сайт работает и в корне, и в подпапке.
2. **Открыть сайт для индексации.** Все страницы в репозитории и в релизах закрыты от поисковиков. В `<head>` каждой HTML-страницы есть строка с меткой `PREVIEW-NOINDEX`:

   ```html
   <!-- PREVIEW-NOINDEX: удалить эту строку при публикации на боевом домене --><meta name="robots" content="noindex, nofollow">
   ```

   Эту строку нужно удалить целиком во всех HTML-файлах. Сейчас это `index.html`, `special-version/index.html`, `privacy.html` и `consent.html`. Удалить разом (из папки с распакованным сайтом):

   ```bash
   grep -rl 'PREVIEW-NOINDEX' --include='*.html' . | xargs sed -i '/PREVIEW-NOINDEX/d'
   ```

3. Проверить, что метки не осталось: команда ниже ничего не должна вывести.

   ```bash
   grep -rl 'PREVIEW-NOINDEX' .
   ```

4. **Обложка превью ссылки.** В `index.html` и `special-version/index.html` мета-тег `og:image` уже указывает на боевой домен: `https://xn--90ahaidkb3bh0b3f.xn--p1ai/assets/og-cover.jpg` (крепкиезубы.рф в punycode). Если сайт будет на другом домене или не в корне, поправьте адрес.

`robots.txt` и `sitemap.xml` для боевого домена готовит разработчик: в релиз они не входят.

## Для разработчика: формы заявок

Отправку заявок подключаете вы: сейчас формы проверяют поля и показывают сообщение об успехе, но данные никуда не уходят.

- **Где формы.** Две формы в `index.html`: окно записи (`#bookingModal form`, открывается всеми кнопками с атрибутом `data-open-modal`) и форма в блоке внизу страницы (`form.cta__form`).
- **Куда вставить отправку.** Функция `submitLead(form)` в `js/app.js` — сейчас пустая. Её вызывают обе формы после успешной проверки. Все поля доступны как `new FormData(form)`.
- **Проверки до отправки.** Телефон заполнен полностью, отмечены обе галочки согласия.

| Поле | Что в нём |
|---|---|
| `name` | имя |
| `phone` | телефон в формате +7 (XXX) XXX-XX-XX |
| `consent_personal_data` | согласие на обработку персональных данных (`on`, обязательно) |
| `consent_marketing` | согласие на рекламные рассылки (`on`, обязательно) |
| `form_source` | откуда заявка: «Окно записи» или «Блок формы внизу страницы» |
| `form_title` | заголовок формы в момент отправки, например «Рассчитать стоимость» |
| `form_trigger` | текст кнопки, которой открыли окно, например «Записаться на консультацию» |
| `form_section` | блок страницы с этой кнопкой, у карточек услуг — с названием услуги |
| `page_url` | адрес страницы в момент отправки |
| `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term` | метки рекламы; запоминаются при первом заходе на сайт (sessionStorage) |

Служебные поля заполняет функция `fillLeadMeta()` в `js/app.js` прямо перед отправкой.

## Превью

**https://panchishen.github.io/dominanta-landing/** — ссылка для согласования с заказчиком.

- Обновляется автоматически при пуше в `main`, если изменилось что-то в `site/`.
- Закрыто от поисковиков меткой `PREVIEW-NOINDEX`. Деплой (`.github/workflows/pages.yml`) проверяет, что метка есть на каждой странице. Если её нет хотя бы на одной, превью не выкладывается.
- Каждая новая HTML-страница в `site/` должна содержать эту строку в `<head>`.

## Как выпускается релиз

1. Заказчик согласовал состояние превью.
2. На этот коммит ставится тег `vX.Y` и создаётся GitHub Release с `site.zip` и списком изменений. Метка noindex в релизе остаётся: её снимает разработчик при публикации.

## Локальный запуск

```bash
node serve-site.js
```

Откроется на http://localhost:5055.
